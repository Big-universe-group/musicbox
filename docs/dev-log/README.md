# 开发记录（dev-log）约定

目的：每轮对话（turn）结束后，把与本项目有关的问题、结论和改动记一笔；之后手动整合成 `需求变更记录.md`。

```text
docs/dev-log/
├── README.md              ← 本约定
├── 需求变更记录.md         ← 整合后的正式文档（手动整合时才改）
└── inbox/
    └── <YYYY-MM-DD>/
        ├── Index.md       ← 当天清单：每条一行
        └── <主题短标题>.md ← 一个 turn（或同一主题的连续几个 turn）一篇
```

## 什么时候记

1. 任何涉及本项目的 turn 都记：需求提出 / 变更 / 撤销、设计决策、代码改动、排查结论、对项目结构的问答
2. 不记：用户说「不用记录」、闲聊、与本项目无关的问题
3. 同一主题的后续 turn（追问、回滚、改方案）追加到同一篇，不另开；回滚或推翻要写明「撤销了什么、改成什么」

## 单篇格式

```markdown
# <主题短标题>

- 日期：<YYYY-MM-DD>
- 类型：需求变更 | 设计 | 实现 | 问答 | 回滚
- 分支 / 提交：<分支> `<短 hash>`（没有提交写「未提交」，非 git 项目写「无」）

## 问题
用户原话的一两句摘要。

## 结论 / 回答
要点式，写决策和理由，不复述过程。

## 改动
- 文件或目录：做了什么

## 对需求的影响
新增 / 变更 / 撤销了哪条需求；没有写「无」。

## 待办
没有写「无」。
```

`Index.md` 每条一行：`- <主题> [类型] → <一句话结论>`。

## 整合

手动触发（例如「整合 dev-log」）时：

1. 按 `inbox/` 日期顺序读，把「对需求的影响」合并进 `需求变更记录.md` 对应章节，回滚的条目以最终状态为准
2. 合并完删除已处理的日期目录
3. 整合前不改 `需求变更记录.md`
